# Architecture Decisions (قرارات المشروع)

> **قاعدة:** أي تغيير في الـ Schema أو الـ Architecture يجب توثيقه هنا مع ذكر السبب.

---

## 1. القرارات المعتمدة حالياً (Approved Decisions)

| القرار | التفاصيل |
| :--- | :--- |
| **RAG Assistant** | إلزامي في الـ MVP مع إظهار المصدر والصفحة، وخاصية الاعتراف بعدم كفاية المعلومات بدل التخمين. |
| **Airflow** | مطلوب لتنسيق وتشغيل خطوات الـ Pipeline وتسجيل الـ Logs والـ Retries. |
| **Lakehouse Architecture** | تقسيم البيانات إلى طبقات Bronze / Silver / Gold كهدف أساسي. |
| **Delta Lake + Parquet** | الخيار المبدئي للتخزين والمعالجة، مبدئياً على Databricks Free Edition بشرط نجاح الـ POC. |
| **OCR** | اختياري؛ نبدأ باستخراج النص الرقمي من الـ PDF، والـ OCR مخصص فقط للمستندات الممسوحة. |
| **FastAPI + Streamlit** | طبقة العرض والربط تكون خارج Databricks في البداية لتقليل التعقيد. |

---

## 2. قرارات قيد التحقق (Pending Validation / POC)

- [ ] **مصادر البيانات النهائية:** التحقق العملي من الحقول وتكرار التحديث وشروط الاستخدام.
- [ ] **الربط مع Databricks:** طريقة الاتصال العملية بين Databricks والتطبيق الخارجي.
- [ ] **Vector Store & Embeddings:** اختيار الموديل المناسب حسب قيود الموارد (محلي vs سحابي).
- [ ] **قاعدة بيانات تشغيلية (PostgreSQL / SQL Server):** التحقق هل نحتاجها فعلاً أم نكتفي بالاستعلام المباشر من الـ Lakehouse.
- [ ] **حدود Databricks Free Edition:** هل تكفي للتشغيل أم نحتاج بديلاً محلياً (Local Spark / DuckDB).
